## 2. 数据库（SQLite，WAL；金额 int64 分）

```sql
CREATE TABLE users(            -- 预置账号，password 存演示哈希
  id INTEGER PRIMARY KEY, username TEXT UNIQUE NOT NULL, password_hash TEXT NOT NULL,
  role TEXT NOT NULL,          -- manager/user/reception/staff/service
  display_name TEXT NOT NULL);
CREATE TABLE pets(
  id INTEGER PRIMARY KEY, owner_id INTEGER NOT NULL REFERENCES users(id), name TEXT NOT NULL);
CREATE TABLE time_slots(
  id INTEGER PRIMARY KEY, start_at TEXT NOT NULL, end_at TEXT NOT NULL,
  capacity INTEGER NOT NULL DEFAULT 3, status TEXT NOT NULL DEFAULT 'open'); -- open/closed
CREATE TABLE bookings(
  id TEXT PRIMARY KEY,                     -- B+日期+序号
  slot_id INTEGER NOT NULL REFERENCES time_slots(id),
  user_id INTEGER NOT NULL, pet_id INTEGER NOT NULL,
  status TEXT NOT NULL,                    -- pending_payment/confirmed/cancel_review/cancelled/
                                           -- checked_in/in_service/completed/no_show/closed/payment_anomaly
  cancel_reason TEXT, review_decision TEXT, review_note TEXT, no_show_reason TEXT,
  created_at TEXT NOT NULL, paid_at TEXT, pay_deadline TEXT NOT NULL,
  UNIQUE(slot_id, pet_id));                -- 同宠物同时段唯一（含历史，业务层过滤有效态判断）
CREATE TABLE slot_taken(                   -- 名额占用（每个未终态预约一行），释放即删
  booking_id TEXT PRIMARY KEY REFERENCES bookings(id), slot_id INTEGER NOT NULL);
CREATE TABLE payments(
  id TEXT PRIMARY KEY, booking_id TEXT NOT NULL REFERENCES bookings(id),
  amount INTEGER NOT NULL, status TEXT NOT NULL,      -- initiated/paid/failed
  channel_txn TEXT UNIQUE,                 -- 渠道交易号全局唯一 → 不得归属两个订单
  created_at TEXT NOT NULL, paid_at TEXT);
CREATE TABLE payment_notifications(        -- 全部回调留痕（含验签失败/金额不符）
  id INTEGER PRIMARY KEY, channel_txn TEXT, booking_id TEXT, amount INTEGER,
  sig_ok INTEGER NOT NULL, result TEXT NOT NULL, handled TEXT NOT NULL, received_at TEXT NOT NULL);
CREATE TABLE refunds(
  id TEXT PRIMARY KEY, booking_id TEXT NOT NULL, payment_id TEXT NOT NULL,
  amount INTEGER NOT NULL, status TEXT NOT NULL,     -- pending/success/failed
  fail_reason TEXT, attempt INTEGER NOT NULL DEFAULT 1, created_at TEXT NOT NULL, done_at TEXT);
CREATE TABLE service_records(              -- 核销/开始/完成各一行，收入按 completed 去重计算
  id INTEGER PRIMARY KEY, booking_id TEXT NOT NULL, action TEXT NOT NULL,
  operator_id INTEGER NOT NULL, created_at TEXT NOT NULL,
  UNIQUE(booking_id, action));              -- 每动作只记一次 → 重复核销/完成天然拒绝
CREATE TABLE audit_logs(
  id INTEGER PRIMARY KEY, actor_id INTEGER, action TEXT NOT NULL, detail TEXT, created_at TEXT NOT NULL);
```

## 3. 并发与幂等设计

| 问题 | 方案 |
| --- | --- |
| 并发抢位超额 | `BEGIN IMMEDIATE` 事务内 `COUNT(slot_taken)+预约唯一约束` 双保险；单写者模型（SQLite）天然串行化 |
| 同宠物同时段重复预约 | bookings 唯一索引 + 业务层有效态过滤 |
| 取消 vs 核销并发 | 两操作在同一事务内以 `SELECT status` 为准做条件更新（CAS），后到者返回明确冲突 |
| 重复支付通知 | channel_txn 唯一约束 + 处理结果表幂等判断 |
| 重复关闭释放名额 | slot_taken 主键删除幂等 |
| 重复核销/完成 | service_records 唯一(booking_id, action) |
| 重复退款 | refunds 单条 pending，重试更新 attempt，不新增单 |
| 待付款超时 | 后台 goroutine 每 5s 扫描 pay_deadline 过期者关闭（可配置教学时钟注入） |

## 4. 时间与教学时钟

`internal/clock.Clock` 接口：`Now()`；生产实现读系统时间，测试实现手动推进。待付款 5 分钟、≥2 小时取消线按时钟判断，演示可配置缩短（`--pay-ttl`、`--cancel-window` 启动参数，页面注明）。

## 5. 接口清单（页面 + JSON）

| 方法/路径 | 角色 | 说明 |
| --- | --- | --- |
| POST /login, POST /logout | 全部 | 预置账号登录，签发 HttpOnly 会话 cookie |
| GET / | 按角色 | 重定向到对应工作台 |
| GET /user, POST /user/book, POST /user/pay, POST /user/cancel | user | 预约/发起支付/取消（≥2h 自动、<2h 转审核） |
| POST /api/mock/notify | 渠道 | 支付/退款回调，HMAC-SHA256 验签（密钥环境变量注入） |
| GET /front, POST /front/checkin | reception | 核销（条件：已确认+无待审+本店） |
| POST /staff/start, POST /staff/finish | staff | 服务开始/完成 |
| GET /service, POST /service/review, POST /service/refund-retry, POST /service/anomaly-refund | service | 取消审批、退款重试、异常支付退款 |
| GET /manager, POST /manager/slot, POST /manager/noshow | manager | 建时段、标记未到店、收店核查汇总 |
| GET /health | — | 健康检查 |

越权控制：所有身份取自会话；user 操作校验 booking.user_id；员工操作校验角色与门店归属；渠道回调校验签名。

## 6. 模拟支付渠道（internal/mockchannel）

内置于同进程但独立路径 `/mock/*`（演示页可操作）：受控返回 成功/失败/超时后成功/重复通知；演示时通过页面按钮或 curl 触发，测试用例直接构造通知。渠道与业务共享 DB 仅为演示简化，回调仍走 HTTP + 验签，保证接口真实性。

## 7. 测试策略（对应题面 §1.6）

- 单测：booking/payment 两核心包 + clock/httpapi handler，覆盖率各 ≥85%。
- 并发用例：20/50 goroutine 抢位、取消 vs 核销并发 50 次，`-race` 下可重复执行。
- 集成：内存 SQLite 全链路用例（预约→支付→核销→完成；迟到支付；退款失败重试）。
