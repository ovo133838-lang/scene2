# Skill：宠物预约业务约束检查（业务专项 Skill）

- **名称/版本**：petshop-booking-check v1（自编）
- **用途**：对题目02 关键业务约束做专项检查——名额占用、预约时间、取消政策、服务进度、退款之间的跨环节一致性。
- **触发场景**：开发 Agent 完成一个业务模块后自检；测试 Agent 设计用例前核对规则覆盖；学生审核 AI 产出时。
- **输入**：题目02 题面规则（§业务范围与规则 1–8）+ 被检代码/数据库快照/接口响应。
- **执行步骤**：
  1. 状态合法性：枚举 bookings.status 迁移，验证不存在题面未定义的迁移路径（如 closed→confirmed、cancelled→checked_in）。
  2. 名额一致性：对每个时段校验 `有效预约数(待付款/已确认/取消待审核/已核销/服务中/已完成) ≤ 3`，且 slot_taken 行数与有效预约数相等。
  3. 宠物唯一性：同一 (slot_id, pet_id) 不存在两条未终态记录。
  4. 取消政策：开始前 ≥2h 的取消不得出现 cancel_review 状态；<2h 的取消必须留有原因且经客服批准/拒绝；待审核预约不得存在核销记录。
  5. 金额守恒：对每个预约核对 支付流水合计 − 退款成功合计 与其状态应有的收款口径一致；已完成服务笔数 = service_records 中 completed 去重数。
  6. 幂等抽检：同一 channel_txn 不得对应两条 paid 支付；同一 (booking_id, action) 不得有多条 service_records。
  7. 权限抽检：越权操作（他人预约、非本店核销）应有拒绝记录。
- **输出格式**：`检查项 | 结果(通过/失败/不适用) | 证据(数据或代码位置) | 失败影响`，末尾给出汇总结论与需修复清单。
- **失败处理**：任一检查失败 → 输出缺陷条目（含复现数据），交回开发 Agent 修复后重新执行全部步骤，不得只复测失败项。
- **完成标准**：7 组检查全部通过或不适用（附依据），无未处置失败项。
