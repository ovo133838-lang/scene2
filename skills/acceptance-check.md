# Skill：题目02 验收检查（验收检查 Skill）

- **名称/版本**：petshop-acceptance-check v1（自编）
- **用途**：依据原始题面（D:/Desktop/Go项目业务场景题.md 题目02 + 第一部分）对最终版本逐项验收，产出可核查的验收报告。
- **触发场景**：测试通过、申请合并 main 之前；验收 Agent 独立会话中执行。
- **输入**：原始题面、被验收 commit 哈希、完整源码、测试报告、覆盖率原始输出、部署地址、`docs/01-需求分析.md` 假设清单。
- **执行步骤**：
  1. 读取原始题面（不得以开发/测试声明替代），列出逐项验收清单（规则 1–8 + 五组演示场景 + 第一部分共同要求）。
  2. 代码核对：对照状态机与技术设计检查状态迁移实现、幂等键、事务边界、越权校验、敏感信息。
  3. 实际运行：按验收环境启动服务，操作五组演示场景（正常接待/名额循环/取消分支/现场冲突/收店核查），记录每步真实响应。
  4. 质量证据核查：`go vet`、`go test -race`、覆盖率原始输出（整体与核心包 ≥85%），核对提交版本对应关系。
  5. 异常路径抽测：重复支付通知、迟到支付、取消 vs 核销并发、退款失败重试、非本店操作。
  6. 假设核对：每个实现取舍能对应假设清单条目，无未登记的猜测。
- **输出格式**：`docs/06-验收报告.md`——逐项 `编号 | 要求摘要 | 结论(通过/不通过) | 证据位置（命令输出/截图/代码行）`，末尾总结论与遗留风险。
- **失败处理**：任何一项不通过 → 验收整体判不通过，出具缺陷清单退回开发；修复后须重新执行全部步骤并记录复验版本。
- **完成标准**：全部清单项通过且证据可追溯；验收报告与被验收 commit 哈希绑定。
